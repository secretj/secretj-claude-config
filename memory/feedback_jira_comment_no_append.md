Jira 티켓에 **판단이 바뀔 때마다 새 댓글을 덧붙이지 않는다.** 중간 과정(방향 전환·리뷰 반영·범위 축소)은 PR 본문에 남기고, 티켓에는 최종 결론을 한 번만 올린다.

댓글을 잘못 올렸거나 문법이 깨졌을 때도 **정정 댓글을 붙이는 것은 오답이다.** MCP에 댓글 수정·삭제 도구가 없으므로([[reference_jira_description_markdown]]), 올바른 본문을 파일로 만들어 사용자에게 전달하고 UI에서 직접 붙여넣게 한다.

**Why:** 어느 보안 티켓에서 진행할 때마다 댓글을 붙여 6개까지 늘렸고, 그중 4개가 이미 폐기된 내용이었다. 특히 첫 댓글의 "오탐" 표현은 보안팀이 dismiss로 오독할 위험이 있어 남아 있으면 해롭다. 사용자 지적: "댓글을 왜 자꾸 이어붙여. 붙이지말고 수정을 못하면 나한테 내용을 전달해야지" (2026-08-10)

**How to apply:** 작업 중에는 티켓에 쓰지 않는다. 조치가 확정된 시점에 자기완결적인 댓글 하나만 올린다 — 분류·taint 경로·조치·설계 판단·검증·배포주의사항·별건을 한 댓글에 담아 앞선 댓글 없이도 읽히게 한다. 이미 여러 개 쌓였으면 삭제 대상 목록을 표로 정리해 사용자에게 넘긴다.
