# HTML 기술 메모 포맷

별도 지시가 없으면 이 포맷으로 만든다.

## 톤

- Apple 디자인 계열 — system font stack, 넓은 여백, 무채색 + 절제된 블루 `#06c`
- **차분하고 정적인 기술 메모.** 평서체(`~된다`)로 쓴다
- 금지: 그라데이션 헤드라인, 이모지, 체크마크, CTA 버튼, 그 밖의 설득·세일즈 장치
- 제안 문서면 기대효과만 쓰지 않는다. **고려사항과 리스크를 같은 비중으로** 쓴다
- 본문 문장은 `rules/korean-tech-writing.md` 의 통제 언어 규칙을 따른다

## 구조

1. 글래스 sticky 상단바
2. 메모형 헤더 — eyebrow + 제목 + lead + 메타 테이블
3. **좌측 sticky 목차(TOC) + 본문 2단.** 모바일은 상단 2열 인라인으로 접힌다
4. IntersectionObserver scroll-spy 로 현재 섹션을 강조한다
5. 섹션마다 번호 칩(`01`, `02`…) + 라운드 카드. 홀짝 밴드 배경을 교차한다
6. `scroll-margin-top` 으로 앵커 오프셋을 잡는다
7. 비교표·다이어그램은 무채색 박스로 그린다

## 재사용

**이전에 만든 문서가 로컬에 있으면 그 구조와 CSS 를 그대로 가져오고 섹션 내용만 교체한다.**
`~/Desktop/docs/` 아래 최근 문서를 먼저 찾는다. 없으면 위 명세대로 새로 만든다.

## 푸터·저장 경로

- **푸터**: 한 줄. `{소속} {이름} · {저장소/대상} · {내용} 명세` 형식. "기준: …" 같은 계보·출처 줄은 넣지 않는다
- **저장 경로**: `~/Desktop/docs/(연월)/(이슈번호)-(내용 한글).html` — 연월은 `YYYYMM`. 폴더가 없으면 만든다
- 실제 소속·이름은 로컬 memory(`feedback_html_doc_output`)에 둔다. 이 저장소에는 넣지 않는다

## 차트가 필요하면

`dataviz` 스킬의 팔레트·축·레전드 규칙을 먼저 읽는다. 무채색 기조를 깨지 않는 범위에서 쓴다.
