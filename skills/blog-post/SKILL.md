# 네이버 글 작성 규칙

작업장은 `~/Desktop/blog/` 다. 원고 정본은 `posts/` 아래 한 파일이다.

## ⓪ 먼저 채널을 정한다

**이 판단을 건너뛰지 않는다.** 두 채널은 어미부터 다르고, 블로그 규칙을 카페에 쓰면 반려된다.

| | 블로그 | 카페 |
|---|---|---|
| 원고 파일 | `posts/{번호}.{제목}.md` | `posts/cafe-{번호}.{제목}.md` |
| 발행 현황 | `PUBLISHED.md` (스크립트가 덮어쓴다. 손대지 않는다) | 추적하지 않는다 |
| 읽을 규칙 | 이 파일 + `references/01`~`04` | **`references/05-cafe.md` 를 먼저 읽는다** |

사용자가 채널을 말하지 않았으면 **묻는다.** 추측해서 쓰지 않는다.

## 읽는 순서

| 파일 | 언제 읽나 |
|---|---|
| `references/05-cafe.md` ★ | **카페 글이면 가장 먼저** — 블로그와의 차이표가 여기 있다 |
| `references/02-body.md` ★ | **블로그 본문 쓰기 전 항상** — 어미와 줄바꿈이 문체의 8할 |
| `references/01-title.md` | 제목 확정할 때 |
| `references/03-hashtags.md` | 블로그 태그 짤 때 |
| `references/04-capture.md` | 사진 고르고 캡션 쓸 때 |
| `~/Desktop/blog/05-작업-컨텍스트.md` | 에디터 자동화·시행착오 기록. **§27 카페** / §29 말투 / §30 사진 삽입 / §31 유입 진단 |
| `~/Desktop/blog/automation/README.md` | 툴체인 사용법 |

`05-작업-컨텍스트.md` 는 세션 기록이라 이 저장소에 넣지 않는다. 로컬 작업장에서 읽는다.

## 절대 규칙 — 어기면 되돌리기 어렵다

채널 표시가 없는 규칙은 **두 채널에 모두** 적용한다.

1. **발행·등록은 사용자가 시킬 때만.**
   - 블로그: 기본은 **임시저장까지**. 발행 후 제목·본문을 고치면 재수집 대상이 되어 순위가 초기화된다.
     **발행 레이어는 `Escape` 로만 닫는다.** 레이어 안 버튼을 텍스트로 매칭해 클릭하면 발행 버튼이 걸린다.
   - 카페: 글쓰기창 입력까지만 한다. **「등록」 버튼을 절대 누르지 않는다.**
2. **말투는 채널마다 반대다.**
   - *블로그*: 문장 끝은 `~에요` / `~어요` / `~예요`.
     **평서체(`~이다` `~한다`)와 `~습니다` 는 같은 금지다.** `~잖아요` `~고요` 도 쓰지 않는다.
     사용자가 특정 초안을 칭찬해도 **`02-body.md` 규칙이 우선**이다.
   - *카페*: **`~습니다` 가 주 어미다.** `ㅋㅋ`·`ㅎㅎ` 를 쓰고, 문장 길이를 들쭉날쭉하게 쓴다.
     정갈한 15자 단문을 늘어놓으면 반려된다.
3. **사진 재사용 금지.** 글마다 그 글에서 처음 쓰는 사진만 쓴다. 모자라면 **그 섹션은 사진 없이** 간다.
4. **사진 업로드는 한 장씩 `browser_file_upload` 도구로.** `run_code` 안에서 `waitForEvent('filechooser')` 루프를 돌리지 않는다 — 모달이 쌓이고, 드레인하면 문서 컴포넌트가 삭제된다.
5. **게시 위치는 원고 메모가 아니라 실제 값으로 확인한다.**
   - 블로그: 발행본 URL 의 `categoryNo`
   - 카페: 글쓰기 주소의 `menuid` 와 `…선택됨` 버튼 텍스트
6. 본문 안 `#해시태그` 를 쓰지 않는다. 태그 개수는 **블로그 20~30개(상한 30), 카페 7~10개(하한 5개)** 다.
7. **사용자가 "~라고 들었다"고 한 외부 정보는 사실 확인한다.** 직접 겪은 일은 그대로 쓰고, 전해 들은 규정·수치는 검증한다.
8. **"~라고 적혀 있어요" 식 라벨 읽어주기를 쓰지 않는다.** 뭐라고 쓰여 있는지가 아니라, 그래서 쓰기에 어떤지를 쓴다.
9. **본문에 특수문자를 쓰지 않는다.** `—` `·` `✔` `「」` `&` 대신 **하이픈 `-`** 로 통일한다. (블로그 명문 규칙. 카페 글도 관찰상 따른다)
10. **메뉴판 가격을 줄줄이 나열하지 않는다.** 가격은 주변 대비 체감과 다음에 먹어보고 싶은 메뉴로 풀어 쓴다.

## 블로그 작업 순서

### ① 쓰기 전 — 이길 수 있는 키워드인지 본다

```bash
cd ~/Desktop/blog/automation && python3 kw_scout.py "후보1" "후보2" "후보3"
```

판정은 **경쟁 밀도 × 콘텐츠 장벽** 2축이다. 경쟁이 꽉 차도(≥27) 상위 글이 얇으면 `틈새` 로 잡히고, 그 키워드가 노려볼 만한 것이다. 경쟁 수만 보면 인기 키워드가 전부 포화로 찍힌다.
출력 끝의 `목표치`(본문 글자수·사진 수)를 그 글의 기준으로 삼는다. 기본값 1,800자/15장은 키워드에 따라 과하다.

### ② 쓴 뒤 — 게이트를 통과시킨다

```bash
cd ~/Desktop/blog/automation && ./prepub.sh ../posts/33.새글.md
```

종료 코드 1이면 **올리지 않는다.** 검수·사진계획·키워드정찰을 한 번에 돌린다.
목표치를 조정할 때는 `PHOTOS=9 CHARS=1100 ./prepub.sh ...` 처럼 넘긴다.

상세 스펙(소재·크기·용량·보증)은 문장이 아니라 **마크다운 표**로 쓴다 — `se-table` 로 변환된다.
공식몰 화면이 필요하면 이미지 URL 을 추적하지 말고 **Playwright 요소 캡처**(`el.screenshot()`)를 쓰고 본문에 출처 한 줄을 넣는다.

### ③ 에디터에 올린다

`05-작업-컨텍스트.md` §1(HTML 클립보드 붙여넣기) → §30(사진 2콜 패턴) → §23(소제목 스티커) 순서로 한다.
**붙여넣기 전에 서체(바른히피)와 크기(15)를 둘 다 지정한다** — 크기만 건드리면 서체가 기본값으로 돌아가 HTML 의 `font-family` 를 덮어쓴다.

> **다이렉트 포인트 글**은 「내 템플릿」을 적용하고 **본문 슬롯에만** 쓴다. 공정위 고지·카페 링크·추천인 코드가 템플릿에 이미 있다.
> 본문이 들어간 뒤 `Cmd+A` → `Cmd+V` 를 하면 템플릿 컴포넌트까지 전부 지워진다.

소제목 장식은 아이콘 PNG 업로드가 아니라 **네이버 스티커**를 쓴다(업로드가 아니라 피드 썸네일에 잡히지 않는다. 크기 조절은 안 되고 185x160 고정이다).

## 카페 작업 순서

게이트 스크립트가 없다. 네 단계를 손으로 지킨다.

1. **그 게시판의 최근 글을 읽는다.** 공정위 문구 위치·제목 패턴·분량·종결어미·이모티콘을 확인한다.
2. 원고를 `posts/cafe-{번호}.*.md` 에 쓴다. 글자 수를 공정위 문구 포함·제외 두 값으로 보고한다.
3. 규정 체크표를 확인한다 — 공정위 문구 맨 위 / 블로그 URL 없음 / 제목에 `(우수후기)` 표기 없음.
   **우수후기를 노릴 때만** 500자·사진 3장·해시태그 5개를 추가로 맞춘다. 일반후기는 제한이 없다.
4. 새 탭에서 글쓰기창을 열어 입력한다. **「등록」 은 누르지 않는다.**

상세는 `references/05-cafe.md` 에 있다.

## 하지 말 것

- 자동 발행, 자동 등록, 발행 후 본문 수정
- 채널을 확인하지 않고 쓰기 — 어미가 반대라 전면 재작성이 된다
- 사용자가 에디터에서 직접 고친 문장을 되돌리기 — **읽고 원고 md 에 반영**하는 방향으로 간다
- 확인 안 된 수치·영업시간·스펙 서술 (사용자에게 묻는다)
- 없는 감상 지어내기. 분량이 모자라면 **추가 사실을 요청**한다
