## 1. 어미 — 이게 문체의 8할이다

### 쓰는 어미

| 용도 | 어미 | 예시 |
|---|---|---|
| 기본 서술 | `~해요` `~예요` | 항목이 한 번에 채워져요 |
| 부드러운 마감 | `~답니다` | 저도 이렇게 옮겼답니다 |
| 다음 문장으로 넘길 때 | `~인데요` `~는데요` | 제일 공들인 부분인데요 |
| 이유·배경 설명 | `~거든요` | 따로 필요했거든요 |
| 경험 회상 | `~더라고요` | 계약하고 나서야 알게 되더라고요 |
| 단정 회피 | `~것 같아요` | 한 번 써 보셔도 좋을 것 같아요 |
| 동의 유도 | `~잖아요` `~죠?` | 일정 종류가 섞여 있잖아요 |
| 안내 | `~드릴게요` `~보세요` | 지금부터 정리해 드릴게요 |

### ⚠️ 사용자가 안 쓰는 어미 (2026-09-08 지적)

**`~잖아요` 와 `~고요` 는 쓰지 않는다.** 사용자 본인 말투가 아니다.
**`~습니다`/`~입니다` 체도 쓰지 않는다 (2026-09-28 지시 "~니다 말투 말고 에요 말투로").** 문장 끝은 `~에요`/`~어요`/`~예요` 로 통일한다. 아래 `~합니다` 관련 항목은 이 규칙 이전 기준이다.
`~답니다` `~거든요` 도 남발하면 AI 티가 난다 — 15·16번 발행글에는 거의 없다.

같이 지적받은 것:

- **독자를 설득하려 들지 않는다.** "어른들이 30분씩 서 계시게 하기가…" 같은
  가상의 정서 호소는 통째로 뺀다. **"이랬다 저랬다" 사실만 적는다.**
- 문장을 짧게 끊는다. 한 문장에 이유·감정·권유를 겹쳐 넣지 않는다.
- 기준 글은 `posts/15.홈리아…` — 스펙 표 + 짧은 서술 + `~습니다`/`~어요`.

### ★ 사용자가 직접 고쳐 쓴 말투 (2026-10-06, 35편 발행본에서 관찰)

35편은 내가 올린 초안을 사용자가 에디터에서 손본 뒤 발행했다.
**고친 자리의 말투가 사용자 본인 말투다.** 다음 글은 이쪽에 맞춘다.

| 특징 | 사용자가 쓴 실제 문장 |
|---|---|
| **어미를 늘려 쓴다** `~어용` `~네용` | 「희노애락이 담겨있었어용」 「대왕계란말이를 먹어보고 싶네용」 |
| **`ㅋㅋ`** 를 쓴다 | 「2015년부터 쌓인 사람들의 희노애락이 담겨있었어용 ㅋㅋ」 |
| **느낌표 앞에 공백** | 「야외 테이블은 따로 없어요 !」 「나오더라구요 !」 「시기잖아요 !」 |
| 정리 불릿을 싫어한다 | 마무리의 「정리하면 이래요」 + 3줄 불릿을 **통째로 삭제했다** |
| 메뉴 나열도 싫어한다 | 국물요리 메뉴 나열 문단과 「메뉴판 다섯 장」 줄을 **삭제했다** |
| 다음에 먹을 메뉴는 1개만 | 내가 3개(삼계버섯전골·대왕계란말이·멘보샤) 적은 걸 **1개로 줄였다** |

**`~잖아요` 는 비대칭 규칙이다.** 사용자 본인은 쓴다(「얼마없는 야장의 시기잖아요 !」).
그래도 **내가 쓰면 안 된다** - 2026-09-08 지적이 유효하다. 사용자가 직접 넣은 건 되돌리지 않는다.

**`~어용`/`ㅋㅋ` 를 내가 먼저 쓰지는 않는다.** 사용자가 고치면서 넣는 톤이라,
내 초안은 `~에요`/`~어요` 로 두고 사용자가 올리는 쪽으로 가게 한다.
다만 **마무리를 정리 불릿으로 닫지 않는 것**과 **메뉴/스펙을 나열하지 않는 것**은
내 초안부터 지킨다 (`CLAUDE.md` 절대 규칙 10).


---

### 쓰지 않는 어미

- `~이다` `~한다` `~된다` (평서체) — 기술 메모 톤이라 블로그에서는 딱딱하다
- `~합니다` 단독 반복 — B도 `~합니다`를 쓰지만 `~인데요`와 번갈아 쓴다. 연속 3문장 이상 금지
- 명사형 종결(`~하기`, `~가능`) — 개조식은 `✔` 불릿 안에서만

> **핵심 규칙**: 같은 어미를 연속 2번까지만. 3번째 문장은 반드시 다른 어미로 바꾼다.
> `~해요 / ~해요 / ~답니다` 는 OK, `~해요 / ~해요 / ~해요` 는 수정 대상.

## 2. 줄바꿈 — 두 글의 가장 뚜렷한 공통점

두 글 모두 **한 문장을 2~3줄로 쪼갠다.** 이게 모바일 가독성과 체류시간을 만든다.

### 규칙

- **한 줄 15~25자.** 40자 넘는 줄은 무조건 쪼갠다
- 쪼개는 위치는 **쉼표 뒤** 또는 **연결어미 뒤** (`~고,` `~는데요,` `~라서`)
- **문단은 2~5줄.** 그보다 길면 빈 줄로 끊는다
- 문단 사이 **빈 줄 1개**, 섹션 사이 **빈 줄 2개**

### 예시

```
✕ 나쁨 (한 덩어리)
결혼 준비를 시작하고 제일 먼저 한 일이 엑셀 파일 만들기였는데요. 예식장, 스드메, 예물, 예단, 혼주 한복, 혼수, 신혼여행 적다 보니 항목이 서른 개가 훌쩍 넘더라고요.

✔ 좋음 (쪼갬)
결혼 준비를 시작하고
제일 먼저 한 일이 엑셀 파일 만들기였는데요.

예식장, 스드메, 예물, 예단, 혼주 한복, 혼수, 신혼여행…
적다 보니 항목이 서른 개가 훌쩍 넘더라고요.
```

> 네이버 에디터에 붙여넣을 때 **줄바꿈이 뭉개지지 않았는지 반드시 확인한다.**
> 줄을 합치면 문체가 통째로 무너진다.

## 3. 글 구조 (B의 뼈대)

```
💡오늘의 요약 - {주제}
1) …
2) …
3) …
4) …

안녕하세요!
{자기소개}. :)

{도입 — 문제 상황, 대화체 한 줄 포함}

[이미지]

1. {소제목}
   본문 2~5줄 문단 × 3~4개
   ✔ 불릿 3~5개
   [이미지]

2. {소제목}
   …
   👉 링크

… (소제목 5~6개)

{정리 — ✔ 불릿로 요약}

{마무리 인사}
그럼 지금까지 {필자}였습니다.
감사합니다 :)

👉 링크

※ 면책 문구
```

### 각 부분 규칙

**① 💡오늘의 요약 (B 패턴)**
- 맨 위에 4줄. `1) 2) 3) 4)` 번호
- 글 전체 결론을 미리 준다 → 이탈률이 낮아지고, 검색 스니펫에 잡힌다
- 각 줄 20~30자

**② 인사**
- `안녕하세요!` 로 시작. 느낌표 포함
- 자기소개 한 줄 + `:)` 로 마감
- A: "오늘도 행복한 지니차니네입니다. :)" / B: "안녕하세요. 메대리입니다:)"

**③ 소제목**
- **번호 + 서술형** 또는 **번호 + 질문형** 두 가지만
  - 서술형(A): `한 장으로도 충분해서 좋아요` `성분도 확인해 봤어요`
  - 질문형(B): `1. 두 서비스, 어떤 차이가 있나요?`
- 소제목 자체가 `~해요` 로 끝나도 된다. 명사형(`기능 소개`)은 쓰지 않는다
- **한 글에 소제목 5~6개**

**④ ✔ 불릿**
- 두 글 모두 핵심 도구다. 3~5개씩 묶어서 쓴다
- 기호는 `✔` 고정 (`-` `•` `※` 섞지 않는다)
- 한 줄 30자 이내. 명사구 또는 `~해요` 한 줄
- 불릿 앞뒤에 빈 줄
- **불릿만 연달아 쓰지 않는다.** 불릿 묶음 사이에 반드시 서술 문단이 있어야 한다

**⑤ 링크**
- 본문 중간에 **3~4회 반복** 삽입 (A는 쿠팡 링크 4회, B는 배너)
- 표기는 `👉 hichecky.com` 한 가지로 통일
- 서로 다른 외부 도메인을 여러 개 넣지 않는다 (스팸 신호)

**⑥ 마무리**
- `그럼 지금까지 {필자}였습니다.` + `감사합니다 :)`
- 그 아래 `※` 면책 2줄

## 3-2. 글 유형 — 제품 소개형 vs 정보 공유형

같은 문체라도 **구조가 다르다.** 유형을 먼저 정하고 쓴다.

| | 제품 소개형 | 정보 공유형 |
|---|---|---|
| 검색 의도 | "○○앱 어때?" | "○○ 앱 추천 / 고르는 법" |
| 소제목 | 기능별 서술형 (`1. ~이 있어요`) | **기준별 질문형** (`2. 기준 ① ~하나요?`) |
| 제품 언급 | 글 전체 | **마지막 한 섹션에만** |
| 필수 요소 | 시작하는 법 | **체크리스트 표** |
| 면책 | `※ 제가 직접 개발한 앱입니다` | `※ N번 항목만 제 앱 소개` + `※ 기준은 특정 앱 무관` |

### 정보 공유형 뼈대

```
💡오늘의 요약 - {주제}, 이 N가지만 보세요
1) ~인가  2) ~인가  3) ~인가 …

안녕하세요! …

{도입 — "앱 이름 나열 글은 많은데 정작 ○○은 안 나와 있더라고요"}
{독자에게 지도 주기 — "제 앱 이야기는 맨 아래 N번에만 있어요"}

1. {주제}는 보통 이렇게 무너져요   ← 기준이 왜 필요한지
2. 기준 ① ~하나요?
3. 기준 ② ~하나요?
…
7. 고르기 전 체크리스트            ← 표
8. 제가 만든 앱으로 시작해 보세요   ← 여기서만 제품

{마무리 인사}
※ 면책 3줄
```

### 정보 공유형의 철칙

- **중간에 제품 자랑을 끼워 넣지 않는다.** 그 순간 광고 글로 읽혀 체류시간이 떨어진다
  (기준 글 B가 비교를 다 마친 뒤 "{자사제품}으로 시작해 보세요"를 따로 뗀 이유)
- 도입에서 **"제 앱 이야기는 맨 아래 N번에만 있어요"** 라고 미리 알린다 — 신뢰가 여기서 생긴다
- 기준은 **독자가 직접 확인 가능한 형태**로 쓴다 (`지출 추가 화면에 '낸 사람' 칸이 있는지`)
  → 추상적 기준(`쓰기 편한지`)은 정보가 아니다
- **체크리스트 표는 네이버 표 기능**으로 만든다. 이미지로 넣으면 모바일에서 안 읽힌다
- 경쟁 제품 이름을 쓸 거면 **직접 설치해 확인한 항목만**, **확인 시점을 함께** 적는다
  (B의 `2026년 7월 홈페이지 기준` 패턴). 확인 안 한 스펙은 쓰지 않는다
- `ㅎㅎ` 는 0~1회로 줄인다 — 정보성 글에서는 많으면 가벼워 보인다

## 4. 이모지·특수문자

### ★ 본문에 특수문자를 쓰지 않는다 (2026-10-06 사용자 지정)

사용자: 「특수문자 쓰지마 쓸거면 -를 써」.

**구분·나열·강조가 필요하면 하이픈 `-` 하나로 통일한다.**

| 쓰지 않는다 | 대신 |
|---|---|
| `—` (em dash) | `-` |
| `·` (가운뎃점) | `-` 또는 쉼표 |
| `✔` 불릿 | `-` |
| `「」` `『』` | 따옴표 없이 그냥 쓴다 |
| `&` | `과` / `와` |

아래 §3 ④의 `✔` 불릿 규칙은 **이 규칙으로 대체됐다.** 불릿은 `-` 로 쓴다.

> **제목에도 똑같이 적용한다.** 네이버가 `—` 는 발행 시 `-` 로 바꿔주지만 `·` 는 그대로 남는다.
> 처음부터 하이픈으로 쓴다(35편에서 제목을 고쳤다).

### 이모지

- 쓰는 것: `:)` `ㅎㅎ` `ㅋㅋ` `ㅠㅠ`
- **글 전체에 5~8개 이내.** 문장마다 붙이지 않는다
- `ㅎㅎ` 는 개인 경험 문장 뒤에만 1~2회 (A 패턴)
- 쓰지 않는 것: `★ ♥ !!! ㅋㅋㅋ 😍🔥💯`

## 5. 인칭·시점

- 필자는 `저는` `제가` — 1인칭 경험 서술이 글의 신뢰를 만든다
- 독자는 `~하시는 분이라면` `~해 보세요` `~확인해 보세요`
- **`여러분`은 쓰지 않는다** (두 글 모두 쓰지 않음)
- 실패담·시행착오를 반드시 1개 이상 넣는다 (A: 브랜드 바꿔봤던 이야기 / 체키: 견적 정산 대화 반복)
- 대화체 한 줄을 도입에 넣으면 이탈이 줄어든다 (B: `"둘 다 기업용이라고 하는데, 뭐가 다른 거지?"`)

## 7. 키워드 배치 법칙

| 위치 | 규칙 |
|---|---|
| 제목 | 주력 키워드를 **맨 앞**에 |
| 💡요약 박스 | 주력 키워드 1회 |
| 첫 문단(도입) | 주력 키워드 1회 |
| 소제목 | 보조 키워드를 나눠서 |
| 본문 전체 | 주력 키워드 **5~7회** (그 이상은 스터핑 판정) |
| 보조 키워드 | 각 **3회 이상** |
| 마무리 정리 | 주력·보조 키워드를 ✔ 불릿로 한 번씩 |

억지로 끼워 넣지 않는다. 넣을 자리가 없으면 **문장을 다시 쓴다.**

### ⚠️ 5~7회는 절대 개수가 아니라 밀도로 본다

글이 3,000자로 길어지면 5~7회는 오히려 **부족**하다.
판단 기준은 규칙이 아니라 **내 블로그에서 실제로 순위가 나온 글**이다.

```
기준 = 강변 웨딩스퀘어 글 → 주력 키워드 6.76회 / 1,000자
```

새 글의 밀도를 이 값과 비교해 맞춘다. 위 표의 5~7회는 **1,000자 기준 환산값**으로 읽는다.
스터핑 판정선을 내가 지어낸 절대 규칙으로 정하지 말고,
**이미 통과한 글을 벤치마크로 삼는다.**

### 「~라고 적혀 있어요」를 쓰지 않는다

사용자: 「ECO PACKAGING 2.0이라고 적혀 있어요. 처럼 적힌걸 나타내는건 AI스러워 빼」.

`05-작업-컨텍스트.md` §26 의 「사진 속 사물을 상표·색·재질로 묘사 금지」와 같은 계열이다.

| ✕ | ✔ |
|---|---|
| ECO PACKAGING 2.0이라고 적혀 있어요 | (뺀다) |
| AMERICAN TOURISTER 각인이 들어가 있어요 | 어느 쪽으로 들어도 편해요 |
| 「무료로 제공되는 음료입니다」라고 붙어 있어요 | 생수랑 17차가 무료예요 |

**뭐라고 쓰여 있는지가 아니라, 그래서 쓰기에 어떤지를 쓴다.**

### 상세 스펙은 표로

사용자: 「이런 상세 기능 등을 표로 나타내는게 더 보기쉬워」.

소재·크기·용량·보증·가격 같은 건 문장으로 늘어놓지 말고 **마크다운 표**로 쓴다.
`render_body.py` 가 `se-table` 로 변환한다.

```
| 항목 | 내용 |
|---|---|
| 사이즈 | 68 × 47 × 32 cm |
| 무게 | 3.8 kg |
```

규정·비교처럼 **대상이 여럿인 정보**도 표가 낫다(33편의 유럽 기차 수하물 규정 표).
