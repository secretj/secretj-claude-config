# 캡처 작성 법칙

> 정본은 로컬 작업장 `~/Desktop/blog/04-캡처가이드.md` 다. 이 사본은 조직 식별자만 치환했다.
> 작업장이 있으면 정본을 읽는다. 사본은 작업장 밖에서 쓰기 위한 것이다.

## 1. 개수·크기

| 항목 | 기준 |
|---|---|
| 장수 | **10~15장** (그 이상은 캡션·본문을 채우는 게 유리) |
| 모바일 캡처 폭 | **720px** 로 리사이즈 |
| PC 캡처 폭 | **1200px** 로 리사이즈 |
| 원본 그대로 올리기 | ✕ — 세로 2500px짜리는 스크롤만 길어진다 |

리사이즈 명령 (macOS 기본 도구):

```bash
sips --resampleWidth 720 "파일명.png"
```

> `-Z` 옵션은 쓰지 않는다. 원본보다 큰 값을 주면 **업스케일되어 파일이 수십 MB로 불어난다.**

---

## 2. 배치 법칙

- **이미지만 연달아 두지 않는다.** 네이버는 그 구간을 이탈 위험 구간으로 본다
- 이미지 **바로 아래에 캡션 한 줄**을 반드시 단다
- 소제목 하나당 이미지 1~2장
- 도입부에 1장, 마무리 직전에 1장을 두면 스크롤이 끝까지 이어진다

### 캡션 쓰는 법

- 본문과 같은 어투 (`~해요` `~답니다`)
- 파일명·기능명 나열 ✕ → **화면에서 뭘 보면 되는지**를 쓴다
  - ✕ `살림 허브 화면`
  - ✔ `살림 탭 하나에 결혼식 준비랑 신혼 살림이 같이 있어요`

---

## 3. 촬영 규칙

- **하단 안내 배너·토스트는 닫고** 찍는다 (체키의 "앱처럼 쓰세요" 배너 등)
- **다크모드와 라이트모드를 섞지 않는다.** 한 글은 한 테마로
- **상단 상태바(통신사·시간·배터리)는 잘라낸다** — 컷마다 시간이 달라 편집 티가 난다
- 실명·이메일·전화번호·업체명은 가린다
- 금액은 가려도 되지만 **항목 구성은 가리지 않는다** (그게 정보다)
- 빈 화면(데이터 0건)은 쓰지 않는다 — 설득력이 없다

## 4. 데모 캡처 vs 실사용 캡처

검색 품질 로직(D.I.A.+)이 가장 크게 보는 건 **"이 사람이 실제로 써봤다"는 신호**다.

| | 쓸 곳 |
|---|---|
| 데모/공식 캡처 | 기능 구조를 보여주는 컷 (설정 화면, 빈 상태 안내, 로그인) |
| **본인 실사용 캡처** | **글의 핵심 주장을 뒷받침하는 컷** — 최소 2~3장은 반드시 |

핵심 주장 컷은 데모로 대체하지 않는다.
예: "누가 얼마 냈는지 정리된다"가 주장이면, 결제자별 집계가 실제로 찍힌 컷이 있어야 한다.

## 5. 파일명·폴더

**앱(제품)마다 폴더를 나눈다.** 한 폴더에 섞이면 어느 글의 컷인지 알 수 없다.

```
images/
├── 체키/
└── 품앗이/
```

파일명 규칙:

```
{주력키워드}-{브랜드}-{번호}-{화면이름}.png
```

예: `결혼준비앱-체키-02-결혼식예산.png` · `축의금장부-품앗이-02-방명록확인.png`

- 한글 파일명은 네이버 이미지 검색에 약하게 반영된다
- 번호는 **본문 삽입 순서**와 맞춘다
- 새로 찍은 컷도 같은 규칙으로 이름 붙인다

## 6. Play 스토어 스크린샷을 블로그에 그대로 쓸 때

스토어용 스크린샷은 **헤드라인 문구가 이미지 안에 박혀 있다.** 블로그에서는 양날이다.

| | |
|---|---|
| 좋은 점 | 스크롤하며 훑는 독자에게 요점이 바로 전달된다. 브랜드 톤이 통일된다 |
| 나쁜 점 | **광고 소재처럼 읽혀** 내돈내산 후기 톤과 부딪힌다 |

**판단 기준**: 글 전체가 스토어 컷으로만 채워지면 광고 글로 읽힌다.
스토어 컷을 쓰더라도 **핵심 주장 컷 2~3장은 헤드라인 없는 순수 캡처**로 섞는다.

순수 캡처가 필요하면 에뮬레이터나 실기기에서 다시 찍고,
상단 상태바와 하단 광고 배너를 잘라낸 뒤 같은 폭으로 리사이즈한다.

## 6-1. 사용자가 보내준 사진 처리

직접 촬영한 사진은 **방향이 틀어져 오는 경우가 많다**(세로로 찍었는데 가로로 저장됨).

```bash
sips -r -90 "파일.jpg"                 # 반시계 90도
sips --resampleWidth 900 "파일.jpg"     # 폭 정리
sips -g pixelWidth -g pixelHeight "파일.jpg"   # 확인
```

- **에디터에 넣기 전에 회전을 끝낸다.** 넣은 뒤 발견하면 그 스텝부터 다시 해야 한다.
- 공식 사진과 직접 촬영 사진을 **섞어 배치**한다.
  공식 컷만 있으면 광고로, 직접 컷만 있으면 정보가 빈약해 보인다.
  07번(모바) = 직접 3장 + 공식 7장.
- 직접 촬영 컷의 캡션은 **"저희 집", "제가 설치한"** 처럼 1인칭으로 쓴다 — 실사용 신호가 된다.

## 7. 체크

- [ ] 10~15장인가
- [ ] 모든 이미지에 캡션이 붙었는가
- [ ] 이미지가 3장 이상 연달아 있는 구간이 없는가
- [ ] 테마(라이트/다크)가 통일됐는가
- [ ] 상태바를 잘라냈는가
- [ ] 빈 화면 컷이 섞이지 않았는가
- [ ] 핵심 주장 컷이 실사용 캡처인가
- [ ] 개인정보가 노출된 컷이 없는가
