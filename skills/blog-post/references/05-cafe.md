# 네이버 카페 작성 규칙

대상은 **다이렉트 결혼준비 카페**(cafe id `25228091`)다.
블로그 규칙을 그대로 가져오면 반려된다. 어미·소제목·분량·해시태그 개수가 모두 다르다.

정본은 로컬 작업장 `~/Desktop/blog/05-작업-컨텍스트.md` §27 이다. 이 파일은 그 §27 을 추린 것이다.
에디터 조작 코드와 시행착오 기록은 §27-5 ~ §27-7 에서 읽는다.

---

## 1. 쓰기 전에 그 게시판 글을 먼저 읽는다 ★★

이 단계를 건너뛰지 않는다. 게시판마다 관례가 달라서 직접 읽지 않으면 모른다.

기본값으로 쓰면 15자 단문을 늘어놓는 문체가 나온다. 사용자는 그 문체를 **"너무 AI스럽잖아"** 로 반려했다.
실제 카페 글은 문장 길이가 들쭉날쭉하고, `ㅎㅎ`·`ㅋㅋ`·`!!`·`??` 가 섞이고, 한 문단이 길다.

본문은 iframe 안에 있다. top document 의 `.se-main-container` 로는 잡히지 않는다.

```js
await page.goto('https://cafe.naver.com/f-e/cafes/25228091/articles/{articleId}?boardtype=L&menuid={menuid}')
for (const f of page.frames()) {
  const t = await f.evaluate(() => {
    const e = document.querySelector('.se-main-container')
    return e ? e.innerText : null
  })
  if (t) return t
}
```

읽으면서 다섯 가지를 확인한다 — **공정위 문구의 유무와 위치 / 제목 패턴 / 분량 / 종결어미 / 이모티콘 사용**.

## 2. 블로그와 다른 점

| 항목 | 블로그 | 카페 |
|---|---|---|
| 종결어미 | `~에요`/`~어요`/`~예요`. **`~습니다` 금지** | **`~습니다` 가 주 어미** |
| 소제목 `###` | 쓴다 (4~7개) | **쓰지 않는다** (관찰 6편 전부 0개) |
| 형광펜 `==…==` | 쓴다 | **쓰지 않는다** (관찰 6편 전부 0개) |
| 소제목 스티커 | 쓴다 | 쓰지 않는다 |
| 문단 | 1문장 1줄에 가깝게 잘게 쪼갠다 | **2~4문장을 통으로 묶는다** |
| 본문 분량 | 키워드별 목표치(`kw_scout.py`) | 우수후기 기준 500자 이상 |
| 해시태그 | 20~30개 (상한 30) | **7~10개** (하한 5개) |
| `ㅋㅋ`·`ㅎㅎ` | 쓰지 않는다 | 쓴다 |
| 공정위 문구 | 에디터 「내 템플릿」이 넣는다 | **본문 첫 줄에 직접 입력한다** |
| 본문 외부 링크 | 카페 링크 카드가 들어간다 | **블로그 URL 금지** |
| 적립 상한 | 20건 | **2건** (투어 후기) |
| 발행 종착점 | 임시저장 | 입력 완료, **「등록」 안 누름** |
| 쓰기 전 선행 작업 | `kw_scout.py` 키워드 정찰 | **그 게시판 실제 글 읽기** |
| 게이트 | `prepub.sh` (종료 코드 1이면 중단) | 없다. 아래 체크표를 손으로 확인한다 |

블로그의 **절대 규칙 2(어미)** 는 카페에 적용하지 않는다. 나머지 절대 규칙은 그대로 지킨다.

## 3. 게시판과 URL

| 게시판 | menuid |
|---|---|
| 업체후기(드레스) | `157` |
| 데이트 맛집 소개 | `196` |
| 업체후기(혼수) | 번호 미확인 |

글쓰기 주소는 `https://cafe.naver.com/ca-fe/cafes/25228091/menus/{menuid}/articles/write?boardType=L` 다.

1. 새 글을 쓸 때 **새 탭을 연다.** 기존 글쓰기 탭을 재활용하면 미등록 초안이 날아간다.
2. 게시판은 주소가 자동 선택한다. `button` 중 `…선택됨` 텍스트로 검증한다.

## 4. 공통 규칙

- **공정위 문구를 맨 위에 둔다.** 본문과 같은 크기·색으로 넣는다. 맛집 게시판도 똑같이 넣는다.

  > 다이렉트결혼준비를 소개하면서 다이렉트결혼준비로부터 웨딩소품(부케, 폐백 등)을 구입할 수 있는 포인트를 받을 수 있음.

- **블로그 URL 을 넣지 않는다.**
- 제목 — 업체후기는 `업체명 + 후기 내용` 으로 쓴다. 너무 짧으면 반려된다. **`(우수후기)` 를 쓰지 않는다.**
  맛집은 `지역 + 맛집/데이트 맛집 + 상호 + 추천/후기` 로 쓴다.
- 제목은 문장형으로 쓴다. 키워드 나열형으로 쓰지 않는다.
- **「등록」 버튼을 절대 누르지 않는다.** 사용자가 직접 누른다.

### 우수후기 조건

세 가지를 모두 채워야 한다. 일반후기는 제한이 없다.

1. 본문 **500자 이상** — `ㅋ`·`ㅎ`·`!`·공백·이모지·스티커를 제외한다
2. 직접 찍은 사진 **3장 이상**
3. 해시태그 **5개 이상**

글자 수는 `len(re.findall(r'[0-9A-Za-z가-힣]', 본문))` 로 센다.
**공정위 문구를 포함한 값과 제외한 값을 둘 다 보고한다.**

### 적립 상한

매체마다 따로 집계한다.

| 매체 | 투어 후기 상한 |
|---|---|
| 카페 | **2건** (신부 글 + 신랑 글) |
| 블로그 | **20건** |

카페 2건을 채워도 블로그는 막히지 않는다.

### 해시태그

관찰된 개수는 7~10개다. 공통 꼬리 2개를 고정으로 붙인다 — `#결혼준비` `#다이렉트결혼준비`.
본문 안에 `#` 을 넣지 않는다.

## 5. 내용은 사실만 쓴다

- 사용자가 준 사실과 **사용자가 찍은 사진에 실제로 찍힌 것** 만으로 쓴다.
- 분량이 모자라면 없는 감상을 지어내지 않는다. **사용자에게 추가 사실을 물어본다.**
- 사진에 찍힌 것을 풀어 쓰면 분량이 늘어난다. 신랑 후기는 이 방법으로 180자에서 559자가 됐다.
- 사용자 사실이 전혀 없으면 초안을 쓰되 **"이 문장들은 추측이니 덮어써 달라"고 명시한다.**

## 6. 사진

### 회전하지 않는다 ⚠️

갤럭시 원본 `4000x3000`(EXIF orientation `<nil>`)은 그대로가 정방향이다.
대화창에서 세로로 누워 보여도 브라우저는 똑바로 렌더링한다.
`sips -r 90` 과 `sips -r 270` 을 둘 다 적용했다가 옆으로 누워서 되돌렸다.

```bash
sips --resampleWidth 860 -s formatOptions 85 원본.jpg --out web/xx-01.jpg
cp web/xx-0*.jpg ~/by-upload/
```

`browser_file_upload` 는 홈 디렉터리 아래 경로만 받는다. `/tmp` 는 거부한다.

### 삽입 순서

1. 사진을 **아래에서 위로** 삽입한다. 인덱스가 밀리지 않는다.
2. 삽입할 때마다 문단 목록을 다시 읽어 검증한다. 의도한 문단보다 뒤로 들어가는 경우가 있다.
3. 어긋나면 그 이미지를 클릭하고 `Delete` 한 뒤 재삽입한다. 텍스트는 지워지지 않는다.

캡션은 넣지 않는다. 삽입하면 `사진 설명을 입력하세요.` 플레이스홀더가 생기는데 그대로 둔다.

대표 이미지는 바꿀 수 없다. `button.se-set-rep-image-button` 이 `click({force:true})` 와 좌표 클릭 둘 다 실패했다.
엉뚱한 이미지가 대표로 잡히면 **사용자에게 직접 누르라고 안내한다.**

### 규정상 걸릴 수 있는 사진

금지 대상은 화면 사진, 브로셔, 명함, 화장실, **계단**, 업체와 무관한 것(테이블 위 커피, 가는 길)이다.

걸릴 만한 사진은 **쓰기 전에 사용자에게 알린다.** 사용자가 "다 넣어"라고 하면 넣는다.
신랑 후기에서 계단·층별 안내판·화장실 비밀번호 안내문을 지적했고, 사용자가 재확인해 9장 전부 넣었다.

## 7. 원고 md 에 남길 것

`posts/cafe-{번호}.{제목}.md` 한 파일에 남긴다.

- 게시판 이름과 menuid
- 글자 수 (공정위 문구 포함·제외 두 값)
- 사진 매핑 — 앵커 문장과 그 뒤에 들어갈 사진
- 사용자가 준 사실
- 규정 체크표
- 에디터 입력본

카페 글은 `PUBLISHED.md` 가 추적하지 않는다. 그 파일은 블로그 RSS 기반이다.

---

## 8. 아직 정해지지 않은 것

규칙으로 고정되지 않았다. 해당 상황을 만나면 **사용자에게 묻는다.**

- **말머리** — 선택지 목록과 선택 기준이 없다. 관찰된 1건은 "미선택"이다.
- **제목 대괄호** — `cafe-01` 은 `[아차산역]` 을 썼고 최근 3편은 쓰지 않았다. 금지는 아니다.
- **업체후기(혼수) menuid** — 번호가 기록되지 않았다.
- **본문 분량 상한·권장 구간** — 우수후기 하한 500자만 있다.
- **동영상** — 우수후기 사진 수에 포함되는지, 개수·길이 제한이 있는지 모른다.
- **발행 후 수정 가능 여부** — 블로그는 금지가 명문이지만 카페는 기록이 없다.
- **카페 글 등록 여부·적립 승인 상태를 어디에 기록할지** 정해지지 않았다.
