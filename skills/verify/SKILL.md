# 검증 게이트

"다 됐다"는 보고의 유일한 근거가 "보기에 다 됐다" 가 되면 안 된다. Claude 가 직접 돌릴 수 있는 검사를 돌리고, 그 **출력**을 근거로 붙인다.

## 1. 무엇이 있는지 찾는다

프로젝트 루트에서 다음을 순서대로 확인한다. 추측하지 않는다.

| 생태계 | 확인할 것 |
|---|---|
| Node | `package.json` 의 `scripts` — `test` `lint` `typecheck` `build` |
| Python | `pytest.ini` `pyproject.toml` `tox.ini`, `ruff` / `mypy` 설정 |
| PHP | `composer.json` 의 `scripts`, `phpunit.xml`, `phpstan.neon` |
| Go / Rust | `go test ./...` / `cargo test`, `cargo clippy` |
| 그 밖 | `Makefile` 의 `test` `check` 타깃, CI 설정(`.github/workflows/`) |

## 2. 실행한다

- **변경된 범위만 먼저** 돌린다. 전체 스위트는 그다음이다 (느린 스위트에 막혀 아무것도 못 돌리는 상황을 피한다)
- 테스트가 없는 변경이면 **테스트를 먼저 쓴다.** 정상·실패·경계값 세 갈래로 나눈다
- UI 변경은 스크린샷으로 확인한다. Playwright MCP 나 `/run` 을 쓴다
- 엔드포인트 변경은 실제 호출로 확인한다

## 3. 보고한다

- 돌린 명령과 그 출력(또는 요약)을 함께 쓴다
- **실패하면 실패했다고 쓴다.** 출력을 붙인다
- 건너뛴 검사가 있으면 무엇을 왜 건너뛰었는지 쓴다
- 검사가 아예 없으면 "검증 수단이 없다"고 쓴다. 통과했다고 쓰지 않는다

## 4. 커밋 전

Claude Code 는 `verify` 스킬이 있으면 커밋 전에 이 스킬을 실행한다 (문서·테스트만 바뀐 커밋은 예외).
게이트가 빨간 상태로 커밋하지 않는다. 사용자가 그래도 하라고 지시하면 그 사실을 커밋 메시지 밖에서 알린다.
